### 2. Why area passes (the one call I made)

A pass is only interesting when it opens something you cannot walk to. The chapter pass already opens every room of
a chapter, so a pass for "Potions class" or "return to the common room" would be a key to a door that is already
open. The destinations that genuinely need one are the separate spaces and set pieces:

`Glacius Challenge`, `Marauder's Challenge`, `Carpe Retractum Challenge`, `Shrieking Shack`, `Patronus Challenge`,
`Quidditch Match`, `Dementor Battle`, `Dark Tower/Buckbeak`, `House Cup`, `Bonus Activities` — **ten**.

The 28 reachable tasks stay as checks; their chapter pass is the gate. The pool gets ~10 big keys instead of 28–35
small ones, which is smoother and keeps the "world visit" feel. `mission_passes = areas | tasks | chain` keeps the
other two shapes available (tasks = maximum fragmentation; chain = vanilla order).

### 2.1 Spells and the retreat

Spells stay in the pool: Flipendo is pre-collected, the other nine are items at their spellbook/shop checks
(suppressed vanilla grants, AP item grants the spell). The softlock worry is real, and the answer is three layers:

1. **Return to the common room (Floo)** — the button Austin asked for. From pause (and a shortcut) it reloads the
   chapter's safe room: `GryffindorCommonRoom` where the chapter has one, otherwise the chapter's start room. It is
   always available in free roam and missions, never consumed, and works offline. Disabled only in cutscenes,
   loading and minigames.
2. **Mission snapshot** — the port copies the progress block and AP state on mission entry; the retreat restores
   it. This covers the save made inside an unwinnable mission, which a reload alone cannot fix.
3. **No-self-lock logic** — no spell's check sits behind a gate that requires that spell; the apworld test asserts
   it.

What is left: engine states that disable the pause menu (cutscenes, minigames, duelling — the live matrix tests
which), and missions that mark themselves failed on exit. Those are short and, in the data, not spell-gated.
Everything spatial and every "mission needs the spell" case is escapable.

### C. Tracker and in-game messages

**Page** (pause → Archipelago), Marauder's Map theme, four tabs: Travel, Checks, Items, Status. Drawn by the port
(settings row-table precedent), not the game's APT UI.

**HUD**: optional Remembrall that glows when the current chapter has unchecked locations.

**Input**: pause page plus one gameplay shortcut. Back is taken by the PC Settings page, so pick something else —
a held combo or the Map button (open question).

**Messages**: v1 native parchment toast for "Check sent: …" and "Received: … from …". Stretch: find the game's
text display/queue (subtitles, `GUI_*_HLPTXT_*`, loading tips) and push messages as in-world text. The rule stands:
the toast is the feedback, the page is the log.

Acceptance: page opens in every gamestate in the §6.6 table; counts match the sidecar; one toast per check/item;
no crash when disconnected.

### F. Reward suppression

- Find the grant sites: item add, card bit, points add, **spell grant**; the card module is known (`0x3661C0/C4`,
  `sub_00071840`), the generic item add and the spell grant are not.
- Implement `ap_suppress(check)` at the grant site using the catalog's `reward_class` and `swap`.
- Cards: the entity must still spawn (it is the check); ownership is suppressed until the AP item arrives; set
  completion is re-evaluated on card add.
- Spellbooks: the grant is suppressed and the AP item grants the spell; the open question is whether the story task
  completes on the pickup (fine) or on ownership (then the task waits for the item — test G3).
- Acceptance: one suppressed card, statue and spellbook each grant exactly once, via AP; album and set state
  consistent; turning `suppress_rewards` off restores vanilla.
