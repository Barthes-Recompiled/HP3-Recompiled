# hp3_recomp M0+M1 (fork, skeleton, clean regen on PoA USA) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `hp3_recomp` repo forked from hp1_recomp, renamed to `hppoa`, stripped of Philosopher's Stone code, whose
`port/regen.sh` runs clean on the PoA USA `default.xbe` and links `hppoa.exe`, with the D3D8/DSOUND/XAPI HLE bound
to PoA's library functions.

**Architecture:** The xboxrecomp toolkit (repo root) and the SCDA-derived renderer (`port/src/scda/`) stay as they
are. Hand-written overrides bind to guest functions by name (`sub_XXXXXXXX`), so every hp1 address in the kept
infrastructure files is moved to PoA's address by a new cross-title XDK matcher (`tools/xdk_port/`), which
byte-matches library code with pointers masked (the same idea as `tools/region/xbe_align.py`, across titles instead
of regions). Game-specific PS code is deleted, not ported. M2+ (boot, in game, playable, parity) get their own plans
once the game runs; this plan ends with a linked exe and a bring-up survey that feeds the M2 plan.

**Tech Stack:** MSYS2 UCRT64 GCC 16 + CMake + Ninja; Python 3 + capstone (pipeline, tools, tests as standalone
`py -3 <test>.py` self-checks like `tools/xiso/test_xdvdfs.py`); Git + GitLab (`glab` optional).

**Spec:** `Harry Potter Xbox Decomps\notes\2026-10-30-hp3-port-design.md` (moves to
`docs/superpowers/specs/2026-10-30-hp3-port-design.md` in Task 1).

## Review Focus

1. **A matcher false positive** (an hp1 library address mapped to a PoA function that only *starts* the same):
   expected behaviour is that only unique, full-length, pointer-masked matches on a detected function start are
   accepted; everything else is reported as unmatched, never guessed. Pinned by Task 5's `test_prefix_only_rejected`
   and `test_duplicate_rejected`.
2. **A kept override file still holding a PS address** after the strip, which would silently override an unrelated
   PoA function: expected behaviour is a hard failure. Pinned by Task 6's `check_no_foreign_addrs.py` run in regen.sh.
3. **A wrong XBE in `game/`** (EUR, PS, a modded XBE): expected behaviour is retarget.py stopping and listing the
   supported SHA-1s. Pinned by Task 4 Step 4.
4. **5849 struct layouts differing from 5659** (CDevice offsets, D3D globals in hle_d3d8.cpp): the matcher moves
   functions, not data offsets. Expected behaviour: every data address/offset carried from hp1 is listed in
   `docs/bringup.md` as "unverified for 5849" so M2 checks each one. Pinned by Task 7 Step 5.
5. **The PS build regressing while toolkit fixes and renames land** (Tasks 2-3 happen before the strip): expected
   behaviour is that hp1's own XBE still regenerates and links after each of those tasks. Pinned by their build steps.

### Task 5: Cross-title XDK matcher

**Files:**
- Create: `tools/xdk_port/__init__.py`, `tools/xdk_port/__main__.py`, `tools/xdk_port/match.py`,
  `tools/xdk_port/test_match.py`, `tools/xdk_port/README.md`

**Interfaces:**
- Produces: `match.match_functions(donor: Image, donor_addrs: dict[int, str], target: Image, target_starts: set[int]) -> MatchResult`
  where `Image` = `tools.region.xbe_align`'s loaded-XBE type (reuse it; don't write a second XBE reader) and
  `MatchResult = {"matched": {donor_addr: target_addr}, "unmatched": {donor_addr: reason}}`, reason ∈
  `"no-match" | "ambiguous" | "not-function-start" | "length-mismatch"`.
- Produces CLI: `py -3 -m tools.xdk_port --donor <xbe> --donor-names <json|.c/.cpp files> --target <xbe> --target-functions <functions.json> -o tools/xdk_port/output/map.json`
  where `--donor-names` given C/C++ files extracts `HLE(ADDR, n)` and `sub_ADDR` names plus the trailing `// Name`
  comment when present.

- [ ] **Step 1: Write the failing tests** in `test_match.py` (standalone, synthetic images built in memory like
  `test_xdvdfs.py`):
  - `test_exact_match`: donor fn bytes at 0x1000 appear once in target at 0x5000 (a function start) →
    `matched == {0x1000: 0x5000}`.
  - `test_pointer_masked`: same body but an absolute in-image pointer differs (relocated) → still matched.
  - `test_rel32_masked`: a `call rel32` whose displacement differs → still matched.
  - `test_prefix_only_rejected`: target shares the first 12 bytes but diverges before the donor function's end →
    `unmatched[0x1000] == "no-match"`.
  - `test_duplicate_rejected`: body occurs twice in target → `"ambiguous"`.
  - `test_not_function_start`: single occurrence but not in `target_starts` → `"not-function-start"`.
- [ ] **Step 2:** Run `py -3 tools/xdk_port/test_match.py`. Expected: fails (module missing).
- [ ] **Step 3:** Implement `match_functions`: donor function extent = from its start to the next detected function
  start in the donor (from the donor's disasm `functions.json`); mask 32-bit values that point into the image and
  rel32 displacements of `call`/`jmp`/`jcc` (capstone when available, as xbe_align does); compare the full masked
  extent.
- [ ] **Step 4:** Run the tests. Expected: all pass.
- [ ] **Step 5: Real-data sanity check** (no data committed): match hp1's PS-EUR XBE → PS-USA XBE using the names in
  hp1's `hle_d3d8.cpp`/`hle_dsound.c`, and compare with hp1's `port/region/ps-usa.json` mapping of the same
  addresses. Expected: every matched address agrees with the region map; record counts in `tools/xdk_port/README.md`.
- [ ] **Step 6:** Commit `tools/xdk_port: match XDK library functions across titles`.
